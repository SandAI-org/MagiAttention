灵活 Flash Attention#

为了支持不规则形状掩码的计算，我们实现了 flexible_flash_attention 内核，可通过以下接口调用。

magi_attention.functional.flex_flash_attn.flex_flash_attn_func()#

类似 flash attention 的接口，无需分布式环境、dispatch 或 undispatch。直接调用 magi_attn_kernel 获取注意力输出和 lse。当您不需要上下文并行时，此接口更快。

参数:

  • q (torch.Tensor) -- Query 张量。

  • k (torch.Tensor) -- Key 张量。

  • v (torch.Tensor) -- Value 张量。

  • q_ranges (torch.Tensor, optional) -- 表示注意力掩码的 query ranges 张量。与 index_attn_indices 互斥。

  • k_ranges (torch.Tensor, optional) -- 表示注意力掩码的 key ranges 张量。必须与 q_ranges 一起提供。

  • index_attn_indices (torch.Tensor, optional) -- IndexAttn token 索引。形状：(total_q, num_kv_heads, max_topk)，dtype=int32。值为 逻辑 KV token 位置：batch_idx * S_kv + token_idx。内核内部通过 pos * NHK + kv_head 转换为物理行。使用 -1 作为填充（必须连续位于每行末尾）。与 q_ranges 互斥。内核内部扫描末尾的 -1 条目来确定循环次数和无效数量——无需 Python 端预处理。max_topk（最后一维）必须是 tile_size 的倍数（128，若 swap_ab 则为 64）。该掩码表示理论上支持块级 KV（k_block_size > 1），但目前仅实现了 k_block_size=1（token 级）。

  • q_block_size (int, optional) -- Q 块大小。默认为 1。目前仅支持 1（逐 token 的 Q 粒度）。

  • k_block_size (int, optional) -- K 块大小。默认为 1。目前仅实现了 1（token 级 KV）；未来可能支持 32/64。

  • max_seqlen_q (int | None, optional) -- query 的最大序列长度。默认为 None。若提供，则为 tile_scheduler 启用优化。使用 auto_range_merge（用于块稀疏注意力）时最推荐设置此项。

  • attn_type_map (torch.Tensor, optional) -- 注意力类型映射张量，dtype=torch.int32，默认为 None，即对所有 range 应用全注意力。取值指定每个 token 的注意力类型： - 0：full attention - 1：causal attention - 2：inverse causal attention - 3：bidirectional causal attention 关于注意力类型映射的更多信息见下方 Note。

  • sink (torch.Tensor, optional) -- 可学习的 sink token 张量。默认为 None，即不应用 attention sink。

  • sink_layout (AttnSinkLayout, optional) -- sink token 的布局。默认为 "sh"。可选值："sh"、"ssh"。

  • softmax_scale (float, optional) -- Softmax 缩放因子。默认为 None，即使用 1/sqrt(head_dim)。

  • softcap (float, optional) -- Softcap。默认为 0.0。

  • deterministic (bool, optional) -- 是否使用确定性注意力。默认为 False。

  • sm_margin (int, optional) -- 预留的 SM 数量，在考虑与其他内核（如通信内核）重叠时很有用。默认为 0，即使用所有可用的 SM。

  • disable_fwd_atomic_reduction (bool, optional) -- 是否禁用前向 atomic reduction。默认为 False。 如果您能确保 q_ranges 不重叠， 可以将其设为 True 以获得更好的性能。 q_ranges 中的“重叠”定义为： 如果 q_ranges 中任意两个 q_range 有非空交集，则为重叠。 例如，q_ranges = [[0, 15], [10, 20], [20, 30]] 是重叠的， 因为 q_range1 = [0, 15] 与 q_range2 = [10, 20] 相交， 而 q_ranges = [[0, 15], [15, 20], [20, 30]] 则不重叠。

  • disable_bwd_dkv_atomic_reduction (bool, optional) -- 是否禁用反向 dK/dV atomic reduction。默认为 False。 如果您能确保（反向中使用的）k_ranges 不重叠且已排序， 可以将其设为 True 以获得更好的性能。 k_ranges 中的“重叠”定义为： 如果 k_ranges 中任意两个 k_range 有非空交集，则为重叠。 例如，k_ranges = [[0, 15], [10, 20], [20, 30]] 是重叠的， 因为 k_range1 = [0, 15] 与 k_range2 = [10, 20] 相交， 而 k_ranges = [[0, 15], [15, 20], [20, 30]] 则不重叠。 注意： 此标志只能在 MHA 或 catGQA 下启用。

  • ref_block_size (tuple[int, int], optional) -- 用于内核选择的参考块大小 (M, N)。默认为 None，即使用内部启发式规则。注意： 此标志对稀疏注意力场景有用，但仍在开发中。

  • max_seqlen_q -- query 的最大序列长度。默认为 None。若提供，则为前向 tile_scheduler 启用优化，尤其适用于块稀疏注意力场景。

  • auto_range_merge (bool, optional) -- 是否为相同的 q_range 自动合并 k_ranges。默认为 False。注意： 此标志对稀疏注意力场景有用，但仍在开发中。

  • swap_ab (bool, optional) -- 是否在注意力前向中交换 matmul 运算的 A、B 操作数顺序（即将 C=A x B^T 转置为 C^T= B x A^T）。默认为 False。注意： 此标志对稀疏注意力场景有用，但仍在开发中。

  • pack_gqa (bool, optional) -- 对于 seqlen_q 较小的场景，是否将共享相同 KV head 的 query head 分组到单个计算块 tile 中。当 seqlen_q 较小时，此方法可显著提升块稀疏注意力的计算效率。默认为 False。注意： kblockm 必须能被 qhead_per_khead（num_qhead // num_khead）整除。对于反向传播，此标志仅在 swap_bwd_qk_loop 为 True 时启用。

  • cat_gqa (bool, optional) -- 是否拼接共享相同 KV head 的多个 Q head，以优化 GQA 设置下的反向性能。默认为 False。

  • sparse_load (bool, optional) -- 是否启用稀疏加载模式，以在 k_range 大小较小（< 64）时优化性能。必须与 auto_range_merge=True 一起使用以增强性能。默认为 False。与 index_attn_indices 互斥。

  • equal_k_range_size (bool, optional) -- 仅在 sparse_load=True 时使用。指示是否所有 k_ranges 大小相同，这让内核可以采用 O(1) 的基于除法的游标查找，而非 O(num_steps) 的回退方案。默认为 True（常见情况，如均匀块稀疏）。警告： 当 k_range 大小不同时必须设为 False，否则查找会计算出错误的 token 索引（导致结果错误）。

  • index_attn (bool, optional) -- 是否启用 IndexAttn 内核路径，此时内核直接读取 index_attn_indices 而非使用 q/k ranges。当提供 index_attn_indices 时自动设为 True。默认为 False。

  • swap_bwd_qk_loop (bool, optional) -- 是否在注意力反向中交换 Q 和 K 双重循环的顺序（即从默认的 K 为外层循环、Q 为内层循环 改为 Q 为外层循环、K 为内层循环）。默认为 False。注意： 此标志对稀疏注意力场景有用，但仍在开发中。

  • return_max_logits (bool, optional) -- 是否返回最大注意力 logits，依据 Kimi K2 提出的 Muon QK-Clip 技术：https://arxiv.org/pdf/2507.20534.pdf。默认为 False。

返回:

  • out (torch.Tensor)：注意力输出张量

  • meta (AttnForwardMeta)：注意力前向传播的元信息，

    目前包括 dtype=torch.float32 的 lse (torch.Tensor)，以及 dtype=torch.float32 的 max_logits (torch.Tensor)，若 return_max_logits 为 True，否则为 None。

返回类型:

tuple[torch.Tensor, AttnForwardMeta]

形状：

  • q: (num_tokens_q, num_heads_q, head_dim)

  • k: (num_tokens_kv, num_heads_kv, head_dim)

  • v: (num_tokens_kv, num_heads_kv, head_dim)

  • sink:

    • if sink_layout == "sh": (num_tokens_sink, num_heads_q)

    • if sink_layout == "ssh": (num_tokens_q, num_tokens_sink, num_heads_q)

  • q_ranges: (num_ranges, 2)

  • k_ranges: (num_ranges, 2)

  • attn_type_map: (num_ranges,)

  • out: (num_tokens_q, num_heads_q, head_dim)

  • lse: (num_tokens_q, num_heads_q)

  • max_logits: (num_heads_q,)

分发（Dispatch）#

变长分发（Varlen Dispatch）#

如果您使用的是由 cu_seqlens 定义的掩码（如 varlen full 或 varlen causal 掩码），我们参照 FlashAttention 的 API 设计了类似的接口 magi_attn_varlen_key，方便您快速上手。

magi_attention.api.magi_attn_interface.magi_attn_varlen_key()#

这是一个类似 flash-attn-varlen 的接口，用于从 cu_seqlens_q、cu_seqlens_k、causal 和 window_size 生成 q_ranges、k_ranges 和 attn_mask_type，计算 dist_attn_runtime_key 并生成对应的内部 dist_attn_runtime_mgr。

参数:

  • cu_seqlens_q (torch.Tensor) -- query 的累积序列长度。

  • cu_seqlens_k (torch.Tensor) -- key 的累积序列长度。

  • num_heads_q (int) -- query 的 head 数量。

  • num_heads_kv (int) -- key/value 的 head 数量。

  • head_dim (int) -- 每个注意力 head 的维度。

  • pad_size (int) -- 已弃用。此参数已弃用，将在未来版本中移除。现在它基于调整后的 chunk_size 在内部计算。传入非零值将触发 :class:DeprecationWarning。

  • cp_group_or_mesh (dist.ProcessGroup | DeviceMesh) -- 进程组或设备网格（device mesh）。注意：对于进程组，我们目前仅支持 nccl 后端；对于设备网格，我们目前仅支持 1D 或 2D 网格。

  • causal (bool, optional) -- 若为 True，则所有掩码类型都设为 CAUSAL；否则根据 window_size 确定掩码类型。默认为 False。

  • window_size (tuple[int, int], optional) -- 滑动窗口掩码的 window_size，表示 [window_size_left, window_size_right]。此参数仅在 causal 为 False 时生效；当 causal 为 True 时，要求为 (-1, -1)。默认为 (-1, -1)。

  • dist_attn_config (DistAttnConfig) -- dist attn 配置。在 dist_attn_config 中使用 DispatchConfig(chunk_size=..., uneven_shard=...) 来配置分发参数。

  • chunk_size (int | None) -- 已弃用。此参数已弃用，将在未来版本中移除。请改为在 dist_attn_config 中通过 DispatchConfig(chunk_size=...) 传入 chunk_size。

返回:

指向内部 DistAttnRuntimeMgr 的 key。

返回类型:

DistAttnRuntimeKey

示例

>>> import torch
>>> import torch.distributed as dist
>>> from magi_attention.api import magi_attn_varlen_key, dispatch, undispatch, calc_attn
>>> from magi_attention.config import (
...     DistAttnConfig,
...     DispatchConfig,
...     OverlapConfig,
...     MinHeapDispatchAlg,
...     UniformOverlapAlg
... )
>>> from magi_attention.common.enum import AttnOverlapMode
>>>
>>> # Step1. generate a dist_attn_runtime_key to store and indicate the inner meta info
>>> dist_attn_runtime_key = magi_attn_varlen_key(
...     cu_seqlen_q=torch.tensor(
...         [0, 2048, 4096], dtype=torch.int32
...     ),
...     cu_seqlen_k=torch.tensor(
...         [0, 2048, 4096], dtype=torch.int32
...     ),
...     num_heads_q=16,
...     num_heads_kv=4,
...     head_dim=128,
...     pad_size=0,
...     cp_group_or_mesh=dist.new_group(list(range(4)), backend="nccl"),
...     causal=False,
...     window_size=(-1, -1),
...     dist_attn_config=DistAttnConfig(
...         dispatch_config=DispatchConfig(chunk_size=512, alg=MinHeapDispatchAlg()),
...         overlap_config=OverlapConfig(
...             enable=True,
...             mode=AttnOverlapMode.STATIC,
...             degree=2,
...             min_chunk_size=512,
...             max_num_chunks=64,
...             alg=UniformOverlapAlg(),
...         ),
...     ),
... )
>>>
>>> # Step2. dispatch the global tensors to local tensors
>>> local_x, local_label, local_rope = [
...     dispatch(tensor, dist_attn_runtime_key)
...     for tensor in [total_x, total_label, total_rope]
... ]
>>>
>>> # Step3. apply QKV projection on local tensors
>>> local_q, local_k, local_v = q_project(local_x), k_project(local_x), v_project(local_x)
>>>
>>> # Step4. calculate distributed attention to get the local attention output tensor
>>> local_out, meta = calc_attn(local_q, local_k, local_v, dist_attn_runtime_key)
>>>
>>> # Step5. undispatch local attention output to the global one if needed
>>> total_out = undispatch(local_out, dist_attn_runtime_key)

如果您想在同一训练步中应用多个掩码，可以使用 make_varlen_key_for_new_mask_after_dispatch 为新掩码创建密钥，只需提供 flash-attn-varlen 风格的 varlen 掩码参数和已有的 dispatch 密钥。

新掩码将复用与 dispatch 掩码相同的分发方案，但使用不同的元参数进行计算和通信。

magi_attention.api.magi_attn_interface.make_varlen_key_for_new_mask_after_dispatch()#

根据以 flash-attn-varlen 风格给出的新掩码参数和用于 dispatch 的 key，在 dispatch 之后为新掩码创建一个新的 dist attn 运行时 key。

注意：当您想在同一训练步中应用多个掩码时（如果您的模型采用混合注意力结构），此 API 很有用；在这种情况下，我们只能选择其中一个掩码进行 dispatch，其余掩码应复用相同的 dispatch 方案，但使用不同的元参数进行计算和通信。

警告：在这种情况下，我们无法保证所有掩码在计算上都负载均衡、在通信上都得到优化。

参数:

  • cu_seqlens_q (torch.Tensor) -- query 的累积序列长度。

  • cu_seqlens_k (torch.Tensor) -- key 的累积序列长度。

  • key_for_dispatch (DistAttnRuntimeKey) -- 用于 dispatch 的 key。

  • causal (bool, optional) -- varlen 注意力掩码是否为因果的。默认为 False。

  • window_size (tuple[int, int], optional) -- 滑动窗口掩码的 window_size，表示 [window_size_left, window_size_right]。此参数仅在 causal 为 False 时生效；当 causal 为 True 时，要求为 (-1, -1)。默认为 (-1, -1)。

  • dist_attn_config (DistAttnConfig, optional) -- 可选的新 dist attn 配置。注意：如果不提供，我们将使用与 key_for_dispatch 相同的配置；如果提供，新 dist attn 配置中的 dispatch 配置不会应用于新掩码。

返回:

新掩码的新 dist attn 运行时 key， 其 dispatch 方案与 key_for_dispatch 相同。

返回类型:

DistAttnRuntimeKey

示例

>>> import torch
>>> import torch.distributed as dist
>>> from magi_attention.api import magi_attn_varlen_key, dispatch, undispatch, calc_attn
>>> from magi_attention.api import make_varlen_key_for_new_mask_after_dispatch
>>> from magi_attention.config import (
...     DistAttnConfig,
...     DispatchConfig,
...     OverlapConfig,
...     MinHeapDispatchAlg,
...     UniformOverlapAlg
... )
>>> from magi_attention.common.enum import AttnOverlapMode
>>>
>>> # Step1. generate a dist_attn_runtime_key to dispatch for flash-attn-varlen style mask
>>> # in the following case, we use a causal mask as the key for dispatch, thus it will consider
>>> # computation load-balance, communication optimization and computation-communication overlap
>>> # according to the causal mask pattern
>>> key_for_dispatch = magi_attn_varlen_key(
...     cu_seqlen_q=torch.tensor(
...         [0, 4096], dtype=torch.int32
...     ),
...     cu_seqlen_k=torch.tensor(
...         [0, 4096], dtype=torch.int32
...     ),
...     num_heads_q=16,
...     num_heads_kv=4,
...     head_dim=128,
...     pad_size=0,
...     cp_group_or_mesh=dist.new_group(list(range(4)), backend="nccl"),
...     causal=True,
...     window_size=(-1, -1),
...     dist_attn_config=DistAttnConfig(
...         dispatch_config=DispatchConfig(chunk_size=512, alg=MinHeapDispatchAlg()),
...         overlap_config=OverlapConfig(
...             enable=True,
...             mode=AttnOverlapMode.STATIC,
...             degree=2,
...             min_chunk_size=512,
...             max_num_chunks=64,
...             alg=UniformOverlapAlg(),
...         ),
...     ),
... )
>>>
>>> # Step2. dispatch the global tensors to local tensors with the same key_for_dispatch
>>> local_x, local_label, local_rope = [
...     dispatch(tensor, key_for_dispatch)
...     for tensor in [total_x, total_label, total_rope]
... ]
>>>
>>> # Step3. make a new dist_attn_runtime_key from key_for_dispatch
>>> # for a new mask, such as a sliding window causal mask below,
>>> # with the same dispatch solution as the causal mask used for dispatch,
>>> # i.e. this new key share the same dispatch meta as key_for_dispatch
>>> # but it can handle the computation and communication of the new mask
>>> # and calculate attn correctly as well, though no optimization is applied for now
>>> new_key_for_swa_mask = make_varlen_key_for_new_mask_after_dispatch(
...     cu_seqlens_q=torch.tensor([0, 4096], dtype=torch.int32),
...     cu_seqlens_k=torch.tensor([0, 4096], dtype=torch.int32),
...     causal=False,
...     window_size=(512, 0), # sliding window causal mask
...     key_for_dispatch=key_for_dispatch,
... )
>>>
>>> # Step4. apply QKV projection on local tensors
>>> local_q, local_k, local_v = q_project(local_x), k_project(local_x), v_project(local_x)
>>>
>>> # Step5. calculate distributed attention
>>> # for the causal mask used to dispatch with key_for_dispatch
>>> local_out1, _ = calc_attn(local_q, local_k, local_v, key_for_dispatch)
>>>
>>> # Step6. calculate distributed attention
>>> # for the new swa mask with the new key
>>> # w/o undispatching back and re-dispatching again to avoid OOM
>>> local_out2, _ = calc_attn(local_q, local_k, local_v, new_key_for_swa_mask)
>>>
>>> # Step7. undispatch local attention output to the global one if needed
>>> total_out1 = undispatch(local_out1, key_for_dispatch)
>>> total_out2 = undispatch(local_out2, new_key_for_swa_mask)

灵活分发（Flexible Dispatch）#

如果您使用的掩码不限于 varlen full 或 varlen causal，还包括滑动窗口掩码或其他更多样的类型，我们建议使用 magi_attn_flex_key，如下所示。

magi_attention.api.magi_attn_interface.magi_attn_flex_key()#

这是最灵活的接口，直接传入 q_ranges、k_ranges 和 attn_mask_type 来生成 dist_attn_runtime_key，它存储并指示内部元数据，作为后续 API（包括 dispatch、undispatch、calc_attn 等）的必需参数。

参数:

  • q_ranges (AttnRanges) -- 全局 query ranges。

  • k_ranges (AttnRanges) -- 全局 key ranges。

  • attn_mask_type (str | AttnMaskType | list[str | AttnMaskType]) -- 全局注意力掩码类型（列表），由 str 或枚举 AttnMaskType 或二者的混合组合表示。

  • total_seqlen_q (int) -- query 的总序列长度。

  • total_seqlen_k (int) -- key 的总序列长度。

  • num_heads_q (int) -- query 的 head 数量。

  • num_heads_kv (int) -- key/value 的 head 数量。

  • head_dim (int) -- 每个注意力 head 的维度。

  • pad_size (int) -- 已弃用。此参数已弃用，将在未来版本中移除。现在它基于调整后的 chunk_size 在内部计算。传入非零值将触发 :class:DeprecationWarning。

  • cp_group_or_mesh (dist.ProcessGroup | DeviceMesh) -- 进程组或设备网格（device mesh）。注意：对于进程组，我们目前仅支持 nccl 后端；对于设备网格，我们目前仅支持 1D 或 2D 网格。

  • dist_attn_config (DistAttnConfig) -- dist attn 配置。在 dist_attn_config 中使用 DispatchConfig(chunk_size=..., uneven_shard=...) 来配置分发参数。

  • is_same_source (bool) -- query 张量和 key 张量是否共享同一来源。默认为 True。

  • is_q_permutable (bool) -- query 张量是否可排列变换。默认为 True。

  • is_k_permutable (bool) -- key 张量是否可排列变换。默认为 True。

  • chunk_size (int | None) -- 已弃用。此参数已弃用，将在未来版本中移除。请改为在 dist_attn_config 中通过 DispatchConfig(chunk_size=...) 传入 chunk_size。

返回:

存储并指示内部元数据的 key。

返回类型:

DistAttnRuntimeKey

备注

  1. 对于仅解码器（decoder-only）的 transformer（如 GPT），它按如下方式应用 'self-attn'：

    1. is_same_source 为 True。

    2. q 和 k 都可排列变换，只要它们以相同方式排列。

  2. 对于编码器-解码器（encoder-decoder）的 transformer（如 T5），它按如下方式应用 'cross-attn'：

    1. is_same_source 为 False。

    2. q 可排列变换，但 k 不可。

  3. 对于带有外部编码器的多模态 transformer，它按如下方式应用 'cross-attn'：

    1. is_same_source 为 False。

    2. 由于 self-attn，q 不可排列变换，但 k 可排列变换，甚至可以以不同方式排列。

magi_attention.api.magi_attn_interface.make_flex_key_for_new_mask_after_dispatch()#

根据给出的新掩码参数和用于 dispatch 的 key，在 dispatch 之后为新掩码创建一个新的 dist attn 运行时 key。

注意：当您想在同一训练步中应用多个掩码时（如果您的模型采用混合注意力结构），此 API 很有用；在这种情况下，我们只能选择其中一个掩码进行 dispatch，其余掩码应复用相同的 dispatch 方案，但使用不同的元参数进行计算和通信。

警告：在这种情况下，我们目前无法保证所有掩码在计算上都负载均衡、在通信上都得到优化。不过，我们正在借助动态 dist-attn 求解器进行改进，以便为采用相同 dispatch 方案的每个不同掩码优化计算和通信。

参数:

  • q_ranges (AttnRanges) -- 全局 query ranges。

  • k_ranges (AttnRanges) -- 全局 key ranges。

  • attn_mask_type (str | AttnMaskType | list[str | AttnMaskType]) -- 全局注意力掩码类型（列表），由 str 或枚举 AttnMaskType 或二者的混合组合表示。

  • key_for_dispatch (DistAttnRuntimeKey) -- 用于 dispatch 的 key。

  • dist_attn_config (DistAttnConfig, optional) -- 可选的新 dist attn 配置。注意：如果不提供，我们将使用与 key_for_dispatch 相同的配置；如果提供，新 dist attn 配置中的 dispatch 配置不会应用于新掩码。

  • num_heads_q (int | None)

  • num_heads_kv (int | None)

  • head_dim (int | None)

返回:

新掩码的新 dist attn 运行时 key， 其 dispatch 方案与 key_for_dispatch 相同

返回类型:

DistAttnRuntimeKey

...     total_seqlen_k=4096,
...     num_heads_q=16,

>>> # for a new mask, such as a sliding window causal mask below,
>>> # with the same dispatch solution as the causal mask used for dispatch,
>>> # i.e. this new key share the same dispatch meta as key_for_dispatch
>>> # but it can handle the computation and communication of the new mask
>>> # and calculate attn correctly as well, though no optimization is applied for now

>>> # for the new swa mask with the new key

>>>
>>> # Step7. undispatch local attention output to the global one if needed
>>> total_out1 = undispatch(local_out1, key_for_dispatch)
>>> total_out2 = undispatch(local_out2, new_key_for_swa_mask)

计算注意力#

Roll 函数#

在 dispatch 之后，如果您需要沿序列维度循环移位本地张量，可以使用 dist attn 运行时密钥调用 roll。此功能主要为 Multi-Token Prediction (MTP) 设计，其中标签需要相对于输入 token 移位一个或多个位置。它也可用于其他场景，如相对位置偏移或 shifted-window 模式。

语义上，roll 等价于 undispatch -> torch.roll -> dispatch，但避免了实体化完整的全局张量，将峰值内存从 O(N) 降低到 O(N/P)，并将通信量减少约 P 倍。

magi_attention.api.magi_attn_interface.roll()#

使用点对点通信沿给定维度循环移位已 dispatch 的本地张量。

此功能主要为 Multi-Token Prediction (MTP) 设计，其中标签需要相对于输入 token 移位一个或多个位置。它也可用于其他场景，如相对位置偏移或 shifted-window 模式。

语义上等价于 undispatch -> torch.roll -> dispatch，但避免了实体化完整的全局张量，将峰值内存从 O(N) 降低到 O(N/P)，并将通信量减少约 P 倍。

  • batch_size (int) -- batch 中的序列数量。

  • seq_len (int) -- batch 中每个序列的固定序列长度。

  • device (str, optional) -- 分配张量所在的设备。默认为 "cuda"。

返回:

一对 1D 张量 (cu_seqlens_q, cu_seqlens_k)，各自形状为 [batch_size + 1,]，分别表示 query 和 key 的累积序列长度。

返回类型:

tuple[torch.Tensor, torch.Tensor]

在使用 varlen 掩码时，通常需要将形状为 [batch_size × seq_len, ...] 的张量重塑为 [batch_size × seq_len, ...]。

为便于使用上述 API，我们提供了 squash_batch_dim 函数来合并张量维度。

magi_attention.api.functools.squash_batch_dim()#

将张量从形状 [b, s, ...] 重塑为 [b x s, ...]，即把 batch 维和序列维展平为单一的前导维度。

参数:

x (torch.Tensor) -- 要合并的、形状为 [batch_size, seq_len, ...] 的输入张量。

返回:

形状为 [batch_size x seq_len, ...] 的重塑后张量。

返回类型:

torch.Tensor

此外，如果您已经计算了 cu_seqlens 张量并想基于它生成 varlen 掩码，我们提供了 infer_attn_mask_from_cu_seqlens 函数。此函数可以根据 cu_seqlens、causal、window_size 和 global_window_size 创建四种类型的掩码——varlen full、varlen causal、varlen sliding window 和 varlen sliding window with global attention，并以 (q_ranges, k_ranges, mask_types, total_seqlen_q, total_seqlen_k) 的形式返回结果。

当 global_window_size 设为正整数时，样本中的每个 query 除滑动窗口外，还会关注该样本的前 global_window_size 个 key token，这对于需要某些前缀 token（如系统提示、sink token）全局可见的架构非常有用。为防止信息泄露，相对位置 i 处的 query 只能看到位置 [0, min(global_window_size, i + window_size_right + 1)) 的全局 token。

magi_attention.api.functools.infer_attn_mask_from_cu_seqlens()#

从 cu_seqlens 推断灵活注意力掩码表示的 query ranges、key ranges 及其他参数，广泛用于 varlen 掩码。

参数:

  • cu_seqlens_q (torch.Tensor) -- query 的累积序列长度

  • cu_seqlens_k (torch.Tensor) -- key 的累积序列长度

  • causal (bool, optional) -- varlen 注意力掩码是否为因果的。默认为 False。

  • window_size (tuple[int, int], optional) -- 滑动窗口掩码的 window_size，表示 [window_size_left, window_size_right]。此参数仅在 causal 为 False 时生效；当 causal 为 True 时，要求为 (-1, -1)。默认为 (-1, -1)。

  • global_window_size (int, optional) -- 每个样本中每个 query 除滑动窗口外总会关注的前导 key token 数量。例如，global_window_size=4 表示样本中每个 query token 无论滑动窗口如何，都会关注该样本的前 4 个 key token。为防止信息泄露，相对位置 i 处的 query 只能看到位置 [0, min(global_window_size, i + window_size_right + 1)) 的全局 token，因此样本开头附近的 query 看到的全局 token 较少。仅在 window_size 不为 (-1, -1) 时生效。默认为 0。

返回:

query ranges、key ranges、注意力掩码类型列表、q 的总 seqlen、k 的总 seqlen

返回类型:

tuple[AttnRanges, AttnRanges, list[AttnMaskType], int, int]

推断滑动窗口掩码#

在 MagiAttention 的设计中，我们使用 (q_range, k_range, masktype) 元组来表示一个切片。

对于滑动窗口掩码，我们没有提供专用的 masktype 来直接表示。

但滑动窗口掩码可以分解为现有 masktype 的组合，如 full、causal、inv_causal 和 bi_causal。

如果您不确定如何进行分解，我们提供了 infer_attn_mask_from_sliding_window 函数来为您处理。

magi_attention.api.functools.infer_attn_mask_from_sliding_window()#

仅将一个滑动窗口掩码转换为使用 q_range、k_range 和掩码类型的表示。掩码类型通过 window_size 指定。

参数:

  • q_range (AttnRange) -- 此滑动窗口掩码的 q_range

  • k_range (AttnRange) -- 此滑动窗口掩码的 k_range

  • window_size (tuple[int, int]) -- 滑动窗口掩码的 window_size，表示 [window_size_left, window_size_right]

返回:

处理后的 (q_ranges, k_ranges, masktypes) 三元组，滑动窗口掩码已被切分为三元组表示。

返回类型:

tuple[AttnRanges, AttnRanges, list[AttnMaskType]]

示例

以下是 infer_attn_mask_from_sliding_window 的示例::

>>> q_ranges, k_ranges, attn_mask_type = infer_attn_mask_from_sliding_window(
...     q_range=AttnRange.from_range([5, 15]),
...     k_range=AttnRange.from_range([5, 15]),
...     window_size=(2, 3),
... )

上面的代码表示 [5, 15] x [5, 15] 区域内、窗口大小为 (2, 3) 的滑动窗口掩码。
