测试指南#

测试组织#

测试按被测层归属。即使涉及同一个公开函数，也应区分分布式集成与局部合同。

目录

职责

tests/test_common

核心值对象、协议与 host range 元数据

tests/test_meta

容器、collection 与局部 solver 合同

tests/test_utils

生产工具函数与运行时环境选项解析

tests/test_testing

测试工具与 reference 实现

tests/test_functional

Attention wrapper、autograd 与 runtime 局部合同

tests/test_kernel/cuda

原生 CUDA kernel 合同

tests/test_kernel/cutedsl

CuTeDSL kernel 与架构相关行为

tests/test_kernel/triton

Triton kernel，包括 range operations

tests/test_distributed

进程组、collective 与分布式 API/runtime 集成

tests/test_api

局部公开 API 与 mask 构造合同

tests/test_pipeline.py

端到端 attention pipeline

通过 worker 扫描参数的 kernel 测试仍可归入 test_kernel：启动 worker 本身不表示在测试通信集成。运行前应核对测试基类及要求的 world size。

运行针对性测试#

在仓库根目录执行命令，并按安装指南准备依赖。根据测试 world size 选择足够的 GPU。以下命令使用一张指定 GPU 运行局部测试：

CUDA_VISIBLE_DEVICES=0 CUDA_MODULE_LOADING=LAZY python -m pytest -q tests/test_common
CUDA_VISIBLE_DEVICES=0 CUDA_MODULE_LOADING=LAZY python -m pytest -q tests/test_meta
CUDA_VISIBLE_DEVICES=0 CUDA_MODULE_LOADING=LAZY python -m pytest -q tests/test_functional/test_dist_attn_runtime.py
CUDA_VISIBLE_DEVICES=0 CUDA_MODULE_LOADING=LAZY python -m pytest -q tests/test_kernel/triton/test_range_ops

使用 python -m pytest --collect-only -q tests 核对收集结果，不能据此声称已执行。magi_attention.testing.parameterize 在测试方法内部运行参数组合，因此 pytest item 数不等于参数组合数。分布式测试使用库内 launcher；除非入口明确要求，不要再用 torchrun 重复启动。

编写测试#

普通 CPU 或单 GPU 合同使用 unittest.TestCase 和 unittest.main()。需要进程组或 worker 生命周期时，复用现有分布式基类及 run_tests() 入口。优先使用库内 parameterize、环境切换工具及 tensor 断言；区分精确相等与数值容差。

使用 magi_attention.utils.arch 判断架构，使用版本 helper 设置依赖门禁。不要仅因 CUDA 不可用而跳过 GPU 测试：所需运行环境故障应直接暴露。保留有意义的架构、版本、rank 数量及显式 profiling 限制。

独立测试共享的 helper 放入 magi_attention.testing，仅服务当前用例的小 helper 留在测试模块内。测试模块之间不要互相 import。Profiling 工作负载必须显式启用。

Python 与 C++ common backend#

Common 容器测试在各文件内部选择实现类型。TestAttnRange、TestAttnRanges、rectangle 和 protocol 类验证 Python 实现，其 TestCpp* 子类使用原生类型重复验证合同。测试不切换包的 backend，也不 reload 模块。AttnMask 仅有 Python 实现。未安装原生扩展时跳过其直接实现测试。

python -m pytest -q tests/test_common/test_attn_range.py::TestAttnRange
python -m pytest -q tests/test_common/test_attn_range.py::TestCppAttnRange

Self-attention 元数据及 ground-truth dispatcher suite 还验证 import 时的路由。每个文件通过 multiprocessing spawn 启动自己的 Python/C++ suite，在子进程 import 包之前设置 MAGI_ATTENTION_CPP_BACKEND。启动后立即恢复父进程环境，并检查子进程失败和超时。不递归启动 pytest，也不设置额外的 CI coverage 模式。Backend 设置保留在这些测试内部。

原生 kernel 预编译#

覆盖原生 FFA 变体的测试类声明 precompile_kernel_specs()，尽量与参数矩阵共用常量。新增或移动 suite 时，在 magi_attention.testing.precompile 中登记模块。以下命令只查看 kernel 清单，不启动编译：

python -m magi_attention.testing.precompile --list

该注册表同时服务 CI prebuild 和手动预编译。应与真实测试模块同步，不包含已删除扩展接口。

Kernel backend#

test_pipeline.py 对 五种 kernel backend（ffa、sdpa、sdpa_ol、fa4、cutedsl）进行参数化。各 attn_config 标注适用 backend，自动跳过不兼容的组合。

  • ffa / fa4 / cutedsl：使用 fp16/bf16 运行较长序列配置，以 norm 和 mismatch 容差判定。

  • sdpa / sdpa_ol：使用 fp64 运行较短序列配置，以精确的 EPSILON 容差判定。

Backend 通过 MAGI_ATTENTION_KERNEL_BACKEND 控制，见下文。

测试用例筛选#

可以使用环境变量精确筛选参数化测试用例。所有筛选条件按 AND 组合，只运行满足全部启用条件的用例。

环境变量#

环境变量

参数维度

匹配目标

MAGI_ATTENTION_TEST_WORLD_SIZE

world_size

逗号分隔的整数，例如 2 或 2,4

MAGI_ATTENTION_TEST_ATTN_CONFIG

attn_config

NAME 字段

MAGI_ATTENTION_TEST_NUM_HEADS

num_heads

下划线分隔，例如 (8, 8) 对应 8_8

MAGI_ATTENTION_TEST_HEAD_DIM

head_dim

字符串表示，例如 64

MAGI_ATTENTION_TEST_DTYPE

dtype

字符串表示，例如 torch.float16

MAGI_ATTENTION_TEST_BACKEND

backend

规范 .value，例如 ffa / sdpa / sdpa_ol / fa4 / cutedsl

字典类型参数（如 attn_config）匹配 NAME 字段。Enum 类型参数（如 backend）匹配规范 .value（ffa）、成员 .name（FFA）以及 str()（MagiAttentionKernelBackend.FFA）。其他类型匹配 str() 表示。

注意： overlap_config 和 random_type_mapping 已从 @parameterize 维度移入 FlagCombGenerator flags，由启发式策略选择。MAGI_ATTENTION_TEST_OVERLAP_CONFIG 和 MAGI_ATTENTION_TEST_RANDOM_TYPE_MAPPING 不再生效。

注意： num_heads、head_dims 和 dtype 合为一个 @parameterize 维度（shape_cfg，16 个三元组）。按 world-size 奇偶分组：奇数 world size 运行 8 组，偶数运行另 8 组，每组在四个 world size 上运行。MAGI_ATTENTION_TEST_NUM_HEADS / MAGI_ATTENTION_TEST_HEAD_DIM / MAGI_ATTENTION_TEST_DTYPE 仍匹配解包后的值。

值采用逗号分隔的 fnmatch 模式列表，支持 *、? 等通配符。

使用示例#

# Run only world_size=2
MAGI_ATTENTION_TEST_WORLD_SIZE=2 pytest tests/test_pipeline.py

# Run only world_size 2 and 4
MAGI_ATTENTION_TEST_WORLD_SIZE=2,4 pytest tests/test_pipeline.py

# Run only a specific attn_config
MAGI_ATTENTION_TEST_ATTN_CONFIG=full_attn_14k pytest tests/test_pipeline.py

# Wildcard matching for multiple attn_configs
MAGI_ATTENTION_TEST_ATTN_CONFIG="full_attn_*" pytest tests/test_pipeline.py

# Run only head_dim=128
MAGI_ATTENTION_TEST_HEAD_DIM=128 pytest tests/test_pipeline.py

# Run only MHA (8,8)
MAGI_ATTENTION_TEST_NUM_HEADS=8_8 pytest tests/test_pipeline.py

# Run only float16
MAGI_ATTENTION_TEST_DTYPE="*float16*" pytest tests/test_pipeline.py

# Run only sdpa_ol backend tests
MAGI_ATTENTION_TEST_BACKEND=sdpa_ol pytest tests/test_pipeline.py

# Combined filters: full_attn configs + head_dim=64
MAGI_ATTENTION_TEST_ATTN_CONFIG="full_attn_*" \
MAGI_ATTENTION_TEST_HEAD_DIM=64 \
    pytest tests/test_pipeline.py

# Comma-separated to match multiple values
MAGI_ATTENTION_TEST_ATTN_CONFIG="full_attn_14k,uneven_full_attn_10k" \
    pytest tests/test_pipeline.py

固定 flags（用户预设环境变量）#

如果运行前已设置某个 flag 的环境变量，测试框架会尊重并锁定用户设置，FlagCombGenerator 不会覆盖它。

使用示例#

# Force all tests to use qo_comm=1
MAGI_ATTENTION_QO_COMM=1 pytest tests/test_pipeline.py

# Force deterministic mode
MAGI_ATTENTION_DETERMINISTIC_MODE=1 pytest tests/test_pipeline.py

# Force native grpcoll + high precision reduce
MAGI_ATTENTION_NATIVE_GRPCOLL=1 \
MAGI_ATTENTION_FORWARD_HIGH_PRECISION_REDUCE=1 \
    pytest tests/test_pipeline.py

# Force CUDA_DEVICE_MAX_CONNECTIONS=1
CUDA_DEVICE_MAX_CONNECTIONS=1 pytest tests/test_pipeline.py

# Combine: pin flags + filter test cases
MAGI_ATTENTION_QO_COMM=1 \
MAGI_ATTENTION_TEST_ATTN_CONFIG=full_attn_14k \
    pytest tests/test_pipeline.py

Flag 组合生成器#

测试通过 FlagCombGenerator 自动生成 flags 组合，包括环境变量 flags（如 deterministic_mode、enable_qo_comm）及测试参数 flags（overlap_config、random_type_mapping）。

这些 flags 采用 heuristic 策略组合，避免完整笛卡尔积，减少测试组合数量。

依上下文筛选#

FlagCombGenerator.get_next_valid_comb(test_config, is_valid_fn) 根据当前测试上下文筛除不合法的组合，约束包括：

  • no_overlap 模式不允许 qo_comm=True

  • qo_comm=True 仅允许 disable_mso 或 no_overlap overlap 配置

  • qo_comm=True 不允许 hier_comm=True 或 bwd_hide_tail_reduce=True

  • native_grpcoll=True 不允许 hier_comm=True；当 head_dim != head_dim_v 时，还要求 num_heads_kv * (head_dim + head_dim_v) 为 hidden-size alignment 的整数倍（fp16/bf16 为 256）

  • flatten_head_groups=True 要求 qo_comm=True，并且不能使用 sink 或 return_max_logits

  • fa4 backend 不允许 deterministic、fwd_hp_reduce、bwd_hp_reduce、qo_comm、sink、bwd_hide_tail_reduce

  • sdpa / sdpa_ol backend 不允许 native_grpcoll

  • 等等。

不合法组合不会被浪费，而是延后到其他上下文重试。全部可能组合都不合法时立即抛出 RuntimeError，避免无限等待。

OverlapConfig degree 语义#

OverlapConfig 通过 degree 参数控制 overlap 行为：

degree

含义

0

不 overlap：阻塞通信并合并 attn_arg，不引入 LSE reduce 精度损失

1

本地加 1 个远端 stage，不分块（无多 stage overlap）

N (N>=2)

本地加 N 个远端 stage（静态多 stage overlap）

None

动态模式，由 solver 自动选择最佳 degree

 
# no overlap (highest precision)
OverlapConfig(degree=0)

# no multi-stage overlap
OverlapConfig(degree=1)

# 4-stage static overlap
OverlapConfig(degree=4, mode=AttnOverlapMode.STATIC)

# dynamic overlap
OverlapConfig(degree=None, mode=AttnOverlapMode.DYNAMIC)

架构无关覆盖#

仅对已审核且覆盖不依赖 GPU 架构的 CPU/Python 合同使用 @pytest.mark.arch_independent。类 marker 作用于全部方法，向已标记类新增 GPU 用例前需重新判断。不要仅因 CUDA 数值、梯度、精度/RNG、编译器或 collective 测试很慢，或两个 CI 平台都会运行，就将其标记。

根收集 hook 仅在 TASK_CI_PLATFORM 为 b300 或 b300_fa4 且实际设备是 Blackwell 时跳过这些 item，共享覆盖由 Hopper CI 承担。没有对应 CI profile 时，本地 Blackwell 运行仍完整；--skip-slow、架构及可选依赖限制保持原行为。Marker 改变执行，不改变收集。

Portable runner 在临时工作目录使用绝对测试路径和 --import-mode=append，仍可发现根 hook 并导入已安装 wheel。已跟踪的根 conftest.py 和 tests 参与主包 trigger/portable 输入摘要，因此修改此策略会使原验证失效，无需改变 cache schema。

内存模型实测核对#

内存预算单测只验证解析模型，不启动大型 attention 用例。需要在 Hopper 上显式核对原生 FFA 的内存时，使用 python -m exps.attn.ffa_mem_budget --help 查看手动实验入口。
